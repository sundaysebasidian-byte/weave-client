# Weave Windows 0.3.5 Preview

独立 Windows 10/11 x64 测试版。沿用 Android 的八套外观、订阅→节点选择和图形化分流，
使用桌面侧栏、紧凑连接概览、柔和玻璃层次和响应式控件排列。不是 Android 模拟器封装。
0.3.1 保留八套配色与玻璃材质，重排首页为状态、出口选择、网络设置三个紧凑分区；
订阅与节点并排，流量固定在侧栏底部，小窗口自动改为单列，不再使用大面积状态展示卡。
0.3.2 加宽侧栏，导航按常用功能与工具分组、增大行间留白；设置固定到底部，
上传/下载并排显示，移除常驻版本文字。矮窗口下导航单独滚动，不挤压底部入口。
0.3.3 改为悬浮玻璃侧栏和共享的玻璃卡片模板，包含原生 Acrylic 底层、半透明着色、
内外高光边缘与静态反光层；连接按钮和选中导航有独立材质。浅/深色重调对比度，
白绿、素纸和四套艺术主题保留原配色。装饰曲面限制在窗口边界内，不持续运动。

0.3.4 侧栏再次加宽，六个入口统一为 56 DIP 高度和 10 DIP 间距，设置回到同一导航列表；
底部只保留流量与本地化说明，继续保留玻璃材质和矮窗口独立滚动。

0.3.5 调整桌面文字层级、浅色对比度、控件圆角与反光强度；导航宽度和均匀间距不变。
TUN 同时接管本账户的系统代理，避免浏览器仍指向旧客户端；断开后按所有权恢复旧设置。
节点引导 DNS 与内容过滤 DNS 分离，使用基于 IP 的加密引导解析；业务 DNS 遵守路由规则。
TUN MTU 使用 1500。启动后核验实际 HTTPS 请求，不再把内核就绪等同于网络可用。

## 安装

在独立分支 `codex/windows-v1-preview` 的 **Windows preview** Actions 下载
`Weave-Windows-v3-Setup-x64`，解压后运行 Setup.exe。
便携包 `Weave-Windows-x64-test` 必须完整解压。目标 Windows 10 22H2 / Windows 11，Intel/AMD x64；ARM64 未交付。
未签名预览包可能触发信誉提示，请核对来源与 SHA-256，**不要关闭系统安全保护**。
不修改 Android main，不自动发布 Release。

TUN 需要当前 Windows 用户授权管理员重开，之后再次点击连接；系统代理模式不需要管理员权限。
不要切换到其他管理员账户，否则无法读取原账户的加密订阅。
配置保存在 LocalAppData/Weave，卸载保留。订阅、应用规则及偏好由 Windows DPAPI 加密。
运行时内核需要本机明文配置，断开后尽力清理；不能防护本机管理员或已入侵设备。

## 功能与边界

0.3 新增简体中文 / English：设置 → 个性化 → 语言，立即切换，不重启内核。
菜单、弹窗、校验错误、节点与网站测试结果、分享确认和内置隐私实验均提供双语。
订阅和节点的原始名称不会被翻译；Windows 系统窗口与外部 DNS 测试网站使用各自的语言。
初次启动跟随系统语言（非中文默认英文），之后记住选择。

侧栏与卡片采用 Windows 原生应用内 Acrylic，系统禁用或不支持透明效果时使用实色回退；
上层使用静态透光渐变、双层边缘与分层阴影，不运行连续背景动画或全页面动态模糊。
这是 Windows 上的 Liquid Glass 风格实现，不是 Apple 原生折射材质；高刷帧时间仍需真机验证。
六个页面沿用 Android 的配色，桌面工具栏允许换行，设置分为个性化、网络与隐私说明。

### 手机与 Windows 同步

1. 两端连接同一 Wi-Fi、手机热点或 USB 网络共享。USB 数据线本身不等于网络共享。
2. 发送端勾选订阅后生成分享，Windows 选择能连接手机的局域网地址。
3. 接收端扫码、读二维码图片或粘贴链接；核对发送端显示的六位码。
4. 接收后勾选要导入的订阅并确认；未选内容不导入、不删除。

密文采用 Android `LanTransferCodec` v1 协议，随机 256 位密钥及一次性令牌；有效期五分钟，成功请求一次即关闭。
密钥在二维码/链接片段内，不发送给 HTTP 服务端；**持有整个链接即可解密，因此不要公开分享链接或截图**。
内容传输经过局域网 HTTP，但载荷为经过认证的密文；不能隐藏设备地址、包大小等流量元数据。
Windows 防火墙如询问，仅对可信的专用网络允许，不要关闭防火墙。路由器 AP 隔离或 Android VPN 的局域网拦截可能阻止互传。
只在主动分享期间监听选定地址，不后台配对、不云备份、不自动全量覆盖。YAML ZIP 导出是明文，不等同加密互传。

### 检测不做虚假的安全结论

网站 403/429 是限制访问，不算解锁成功。代理 IP 成功不证明所有应用、DNS、IPv6 都无泄漏。
浏览器实验需要用户同意，仅代表隔离的内置 WebView2；会使用 ipify 和 STUN 服务，可能暴露直连公网地址。
指纹只在本机计算，不上传；DNS 实测明确打开 browserleaks.com/dns，由该第三方处理测试流量。
测试失败/没有证据应视为未知，不是“安全”。需要本机已有 Edge WebView2 Runtime，应用不静默安装。
DNS 引导解析使用 AliDNS / Cloudflare 的 IP 地址 DoH，仅引导解析/节点域名不使用内容过滤 DNS；
业务域名仍使用用户选择的过滤配置。常用 STUN 端口拦截不是完整 WebRTC 防泄漏。

点击连接后会向 Google / YouTube 的 HTTPS generate_204 发起一次有时限的检测（不带账户、Cookie 或订阅信息）。
先通过当前代理端口，TUN 模式再通过系统路由核验；这不是后台轮询，也不是泄漏安全认证。
W-N01 表示代理端口未确认可达；W-N02 表示代理端口可用但系统 TUN/DNS 路径未确认。
目标服务被过滤、临时不可用也可能导致待确认，因此不会仅因检测失败销毁连接或自动降级直连。
若已设置 Windows 自动代理脚本，W-P01 会提示用户自行关闭，不静默删除 PAC 配置。
TUN 就绪检查不是系统级 Kill Switch，核心退出后 Windows 可能恢复直连。

### 流畅与后台开销

页面切换无跳动过渡；列表虚拟化、后台解析、静态阴影/渐变，不持续进行实时全屏模糊。
实时流量在侧栏每两秒读取，最小化暂停；不自动运行网站检测，不绘制连续流量动画。
关闭重复 provider 周期测速，自动组保留惰性健康检查。摄像头只在扫码窗口开启，分析限频，不保存画面。
2× UI 截图用于布局检查，不是刷新率测试；**实际 120/144 Hz 帧时间尚需高刷 Windows 真机测量，不能保证零掉帧**。

## 构建

官方 Mihomo **v1.19.30 amd64-v1**（不是 Android 定制 JNI 核心）：
[对应源码](https://github.com/MetaCubeX/mihomo/tree/v1.19.30)。下载包 SHA-256：
`8b81fe2c5cd04ca6deb61eec6075150b44cc5ad13ab867750642e2422f7c1278`。
需要 VS 2022、.NET 8、Java 17（协议测试）和 Windows App SDK 构建支持；先将同版本内核放入 runtime 目录：

```powershell
.\windows\build.ps1 -Platform x64 -Configuration Release
```

CI 执行核心测试、独立 Java Android 字节协议互操作测试、真实 Mihomo 配置/会话测试，
以及本地模拟 HTTP 上游的自动/手动节点真实转发和 Windows TUN IPv4 转发测试，
WinUI 启动和多页面/主题截图，再生成 Inno Setup 安装包。CI 不能替代真实代理节点及双端设备验收。
