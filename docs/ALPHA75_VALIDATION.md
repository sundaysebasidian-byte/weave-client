# alpha75：节点完整性跟进与探测结果

## 修改边界

- CMFA 的官方 `core/src/main/golang/native/config/fetch.go` 使用原链接与 `ClashMetaForAndroid/版本` 请求标识，再拉取 provider。Weave 不再给 Walless 新链接强制追加旧 `client=cfa&provider=false`。
- 只移除旧版生成的精确参数集合 `client=cfa&provider=false`（可带 `cluster=false`）。含其他自定义参数的链接不执行该迁移；显式 `cluster=true` 保留。提供者子链接仍不改写。无法仅凭 URL 证明这组参数由谁添加，因此迁移刻意限于这两种集合。
- 保留 alpha74 的完整节点对象解析、provider 合并及数量骤减阻止覆盖。新增 23 个根节点加 42 个 provider 节点的合成回归用例；它不是 Walless 真实配置证据。
- 用户确认 CMFA 刷新后仍有 65 个，排除仅旧缓存的解释。已请求脱敏 YAML 对照；尚未收到，因此不宣称恢复真实 65 个，也未刷新或改写手机订阅。

## 探测语义

- 节点选择、订阅详情和质量矩阵显示 0%、部分失败、100% 与成功/总次数。内核缓存延迟不冒充已执行的多轮探测。
- 控制器或读取失败导致该轮检测报错，不把内部错误算成网络丢包，也不静默丢弃失败轮次后显示健康结果。
- 网络与隐私检测：两个 HTTPS 端点各 3 次，按端点顺序、两端并发；单次连接/读取超时各不超过 1500ms。无后台探测。显示每端与总计失败比例，全部失败仍显示 100%。
- 这是 HTTP 探测失败率，受 DNS、TLS、服务器、代理和路径影响，不等同于 ICMP/UDP 数据包丢失。六个样本仅作参考，不是长时间稳定性证明。
- 首次测试发现“成功”标签缺少译文，已补齐并重新验证。
