# Android 连接设置

## Weave Share 局域网设备共享

1. 让两台设备连接同一个可信 Wi-Fi，或让接收设备连接运行 Weave 的手机热点。
2. 在 Weave 打开「设置 → 连接进阶 → Weave Share」，开启共享并连接 Weave。点击「查看共享凭据」。
3. 在接收设备配置 HTTP 代理或 SOCKS5。服务器填写共享面板的手机地址，端口为 7890，用户名和密码使用共享面板显示的值。手机开热点时，也可查看接收设备的默认网关。Android 的 Wi-Fi 代理设置通常用于 HTTP，SOCKS5 需要接收端应用支持。
4. 在接收设备打开需要使用代理的应用并验证访问。Wi-Fi 启用了客户端隔离、系统拦截入站连接，或接收应用忽略系统代理时，连接可能失败。
5. 完成后关闭共享。共享凭据通过 Android Keystore 加密保存。HTTP 和 SOCKS5 的本地代理认证仍经过局域网链路，请在可信网络中使用，避免把代理端口转发到公网。

在共享中心选择「临时授权」，可为接收设备单独设定有效期、双向速率上限和出口节点。接收端使用端口 7891，支持 HTTP 或 SOCKS5 的 TCP 转发，也可用 Weave 扫描配对二维码。二维码包含接收端所需的凭据。授权到期或手动删除会关闭使用该授权的连接。实时拓扑显示在线来源、实际出口和活动连接的流量。

普通共享使用当前默认出口。本机的按应用分流依据本机应用识别信息，因此接收设备的应用不会自动套用本机应用规则。共享仅对主动配置代理的流量生效。其他设备使用自身 DNS 或忽略代理的流量由该设备处理。

## IP 协议与 TUN

Android 版的规则、全局和直连模式均使用 Android TUN，模式决定内核如何处理进入 TUN 的流量。

- 双栈模式接管 IPv4 和 IPv6。
- 仅 IPv4 模式阻止进入 VPN 的 IPv6。启用显式的应用绕过时，被排除的应用仍使用其自身网络。
- 仅 IPv6 模式只为 TUN 配置 IPv6 地址、路由和 DNS，并关闭应用绕过。它拒绝 IPv4 目标并过滤 VPN DNS 的 A 应答。仅有 IPv4 地址的站点或节点可能不可用。代理服务器对外使用的地址族由其自身决定。

## DNS

加密 DNS 负责业务解析。引导 DNS 只用于查询加密解析器的主机名。「加密引导（Cloudflare）」直接连接固定 IP 的 DoT 服务器，不需要明文查询引导服务器的域名。已有引导选择保留；仅 IPv6 时使用相应的 IPv6 地址。

手动 DNS 对比在当前物理网络上进行，每个受测地址只查询固定的 `example.com`。结果包含建立加密连接和收到有效 DNS 应答的用时。DoH 和 DoT 对比显示三次采样的成功次数、延迟中位数和抖动。可输入最多六个上游，支持 DoH、DoT 和 DoQ。DoQ 的当前内核解析可通过「检测当前解析」验证，端点对比暂不单独测量 DoQ。系统断网保护或网络切换可能使检测无法完成。

## 始终开启与重启恢复

系统提供「始终开启的 VPN」时，从 Weave 的「Always-on 与断网保护」进入 Android VPN 设置，为 Weave 打开始终开启。需要系统阻断 VPN 外的流量时，再启用系统选项「无 VPN 时阻止连接」。

在缺少系统开关的设备上，可以在同一页面选择「重启解锁后尝试重连」。这一选项默认关闭。它只在此前有成功连接、VPN 授权仍有效时尝试恢复。手动断开会取消恢复。设备强制停止应用、厂商限制后台启动或重启后网络不可用时，可能需要手动连接。
