# alpha78：首页统计开销优化

## 已定位的无用工作

- DashboardState 的 sessionDurationSeconds 没有任何 UI 消费者，但首页每次统计采样都会更新它。即使节点与流量相同，也导致状态不相等。
- 首页统计原本只在网络检测和默认节点选择弹窗中暂停；其他覆盖首页的弹窗仍允许查询。
- 整个 DashboardState 传入主卡片和出口卡片，使流量数字变化也成为这两张静态卡片的输入变化。

## 调整

- 删除未展示、未持久化的计时字段及计时器状态。运行数据不变时复用状态和节点对象。
- 连续三个零流量样本后，将首页统计间隔从 3 秒降至 15 秒；检测到任一方向流量恢复 3 秒。查询失败有 15 秒退避。
- 所有覆盖首页的应用弹窗均暂停首页查询。后台、滚动暂停行为保留；恢复可见时立即查询，重新开始短间隔采样。
- 对控制状态进行 distinctUntilChanged，单纯状态消息变化不反复重启统计协程。
- 将主卡片与出口卡片的输入限制为各自使用的字段，不改布局、颜色、阴影和交互。

## 范围与验证口径

- 不修改 VPN 前台服务、通知、隧道保活、DNS、安全规则、节点健康检查或网络恢复逻辑。
- 单元测试用 10 分钟连续空闲的虚拟采样序列比较：旧固定周期需要 200 次查询，新策略需要 42 次。这个数字是查询次数，不是耗电降幅。
- 覆盖活跃流量恢复、失败退避、重新可见后的策略重置、重复数据无状态变更及节点切换/延迟更新。
- 未进行实机电池 A/B 测量；用户报告的 75 mAh 与前台时长不足以定位系统电量统计归因。应结合具体机型的统计截图，并保持亮屏时间、网络、节点与业务负载一致再比较。
- 仅生成本地 alpha78 优化预览包，未自动更新 GitHub Release、安装设备或改动用户配置。
