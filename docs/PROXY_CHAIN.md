# Android 链式代理

在「设置 → 连接 → 链式代理」分别选择入口节点和出口节点并启用。Mihomo 的 `dialer-proxy` 使出口节点通过入口节点建立连接；网站看到出口节点的 IP，入口节点与出口节点提供者仍各自可以观察相应链路信息。链式并非匿名保证。

- 可选择用于默认出口，也可只作为规则模式下特定应用的分流目标；本地直连/拒绝规则继续生效。「直连」模式不使用链式代理。
- 入口和出口必须是不同、当前订阅中可唯一识别的节点。订阅重排不会改变选中的节点；节点消失或同名同协议节点产生歧义时，链式配置拒绝启动或重载，不会改走其他节点或直连。删除任一订阅会关闭链式设置，指向链式的应用规则会显式拒绝连接，直到重新配置。
- UDP 型出口经某些入口可能不兼容；连接后应运行内置出口、可达性及隐私检测。不要将“隧道已建立”视为可上网的证明。
- Weave 不在后台新增链式探测；仅使用原有订阅与用户主动运行的检测。

实现参照 [Mihomo `dialer-proxy` 文档](https://wiki.metacubex.one/en/config/proxies/dialer-proxy/)；旧 `relay` 代理组已弃用。
