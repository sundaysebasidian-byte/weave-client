# IP 质量检测

Android 端的 IP 质量检测位于连接首页，只有用户主动点击时运行。它不上传到 Weave 服务，也不把结果写入订阅、日志或诊断包。

## 检测内容

- `api4.ipify.org` / `api6.ipify.org`：分别确认当前可见 IPv4、IPv6 出口。
- `ipwho.is`：读取 IP、国家/地区/城市、ASN、组织/ISP 和第三方代理、VPN、Tor、托管标签。
- Cloudflare trace：读取边缘机房和另一个出口视角。
- Cloudflare 与 Google 的 `generate_204`：各发起 3 次独立的 HTTPS 请求，记录接收 204 响应的应用层耗时。200 登录页、重定向和错误响应不算成功。按端点分别显示成功样本的中位数 P50、P95（不足 2 次不显示）和相邻成功请求耗时变化的平均绝对值。失败请求打断抖动的计算，不是网络丢包率。
- 完整检测还会并行探测 X、TikTok、YouTube、Google、GPT、Claude、Netflix、Facebook 和 Disney+；这些请求只取 HTTPS 响应状态和应用观察到的耗时，不读取网页正文，用来区分“当前出口无法连通”和“服务已响应但需要登录/地区权限”。

打开页面本身不会触发上述检测。点击运行后，请求遵循应用当前的路由规则，可能经代理，也可能直连。这不是到节点的物理链路测量。HTTPS 请求设有超时与响应大小限制。公网地址会拒绝回环、私网、链路本地、组播、CGNAT 和文档保留网段。

[Android 默认网络快照](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)不发包，不读取连接负载：只显示系统报告的 VPN 类型、本地地址族是否存在和已配置 DNS 的数量。读不到显示「—」。这些都是设置或某一瞬间的本地状态，不等同于 DNS 查询路径或真实出口。

下载测速需单独点击。应用向 Cloudflare 的固定测试端点请求 1 MiB，限一笔、8 秒；响应太短、带内容编码、超时或取消都不产生速率。Mbps 使用单调时钟测得的整体时间，包括等待响应头和读取正文。两段时间是应用观测到的，并不是孤立的 DNS、TCP 或 TLS 握手耗时。

## 结果边界

“已确认”只表示对应端点返回了可解析证据，不代表匿名、无恶意或网站一定信任该 IP。地区、ASN 和代理标签由第三方数据库提供，可能过期或误判。DNS 泄漏、WebRTC 候选地址、浏览器 Secure DNS 和网站信誉需要在 Chrome 等真实浏览器中使用外部测试页复核；应用不会把 HTTP 结果冒充这些测试的结论。

出口一致性按 IP 地址族分别比较 ipify、ipwho.is 与 Cloudflare trace；IPv4 与 IPv6 天然不同，不构成冲突。同族地址不同时提示复核，可能是链式代理、负载均衡或切网，不能仅凭这一项认定泄漏；可比证据不足时显示“未知”。内置 WebRTC 测试仅代表应用内的 WebView。外部复核链接则由 Android 交给浏览器打开，不能替代其他应用自身的测试。IPv4 配置下外部站点报告 IPv6 只说明它看见了 IPv6 出口，代理的上游也可能使用 IPv6。
